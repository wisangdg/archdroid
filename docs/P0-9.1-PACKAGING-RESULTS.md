# P0-9.1 — Packaging and release artifact matrix

Build and end-to-end verification results of ArchDroid's packaging on the Tier 1 target, recorded for 0.1.0. Later results are in [P0-8.2-MATRIX-RESULTS.md](P0-8.2-MATRIX-RESULTS.md).

> [!NOTE]
> **Correction (2026-11-03).** This page called the AppImage "universal". The 0.1.0–0.1.3 AppImages were built on Arch and bundle libraries that need glibc 2.44, so they only start on equally new distributions (seen failing on Debian 12). From 0.1.4 the AppImage is built on Ubuntu 22.04 in CI (glibc 2.35 floor) and checked on Debian 12 and Arch. Likewise the `.deb` and `.rpm` are no longer only "previews": see the README support table for what was tested on each distribution.

## 3. Build environment findings and fixes

1. **linuxdeploy's bundled `strip` cannot handle SHT_RELR (`.relr.dyn`)**:
   - Recent binutils on Arch Linux emit a `.relr.dyn` section that the `strip` inside the linuxdeploy AppImage fails on.
   - Fix: the bundler runs with `NO_STRIP=1` through `npm run build:bundles` (`NO_STRIP=1 tauri build`).
2. **The AppImage's AppRun polluted the Python environment**:
   - AppImageKit's `AppRun` sets `PYTHONHOME` and `PYTHONPATH` to paths inside the AppDir.
   - The AppImage ships no full Python runtime, so every Python-based host tool (`/usr/bin/waydroid`) failed with `Fatal Python error: Failed to import encodings module`.
   - Fix:
     - `sanitize_appimage_env()` runs at the start of `archdroid_lib::run()` in `src-tauri/src/lib.rs`.
     - `PYTHONHOME` and `PYTHONPATH` are removed explicitly when host Waydroid commands run, in `src-tauri/src/waydroid.rs`.
     - Unit test `sanitize_appimage_env_cleans_polluted_python_vars`.

## 4. Results in a clean VM (Arch Linux QEMU/KVM)

### A. Arch Linux package (`.pkg.tar.zst`)
- **Install**: `sudo pacman -U --noconfirm archdroid-bin-0.1.0-1-x86_64.pkg.tar.zst`
  - pacman installed the missing runtime dependencies `webkit2gtk-4.1` and `libappindicator`.
  - Files installed: `/usr/bin/archdroid`, `/usr/share/applications/ArchDroid.desktop`, `/usr/share/icons/hicolor/*/apps/archdroid.png`.
- **Desktop entry**: `desktop-file-validate /usr/share/applications/ArchDroid.desktop`
  - Exit 0, no warnings or errors (`Terminal=false`).
- **Shared libraries**: `ldd /usr/bin/archdroid`
  - Every dynamic library resolves.
- **Launch without a terminal**: `gtk-launch ArchDroid`
  - Starts from the standard launcher; the WebView initializes and renders without opening a terminal.
- **Uninstall**: `sudo pacman -R --noconfirm archdroid-bin`
  - Removes all app files and refreshes the desktop/icon caches.

### B. AppImage (`ArchDroid_0.1.0_amd64.AppImage`)
- **Standalone run** (on Arch):
  - Runs both with FUSE 2 (`fuse2` installed) and without FUSE (`--appimage-extract-and-run`).
  - No terminal window pops up.
  - Calls into host Python (`/usr/bin/waydroid status`) work without encoding errors.

### C. Debian (`.deb`) and RPM (`.rpm`) metadata
- `dpkg-deb -I`: package `arch-droid`, Depends `libwebkit2gtk-4.1-0, libgtk-3-0`, valid md5sums.
- `rpm -qip` and `rpm -qpR`: name `arch-droid`, Requires `libwebkit2gtk-4.1.so.0()(64bit)`, `libgtk-3.so.0()(64bit)`.
