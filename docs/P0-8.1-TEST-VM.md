# P0-8.1 — Disposable test VM

This document describes the disposable Arch Linux VM used for the P0-8 live
validation matrix. The VM is **not** the development machine and holds no
personal data.

## Artifacts

Everything lives outside the repository, in `~/archdroid-test-vm/`:

| File | Purpose |
|---|---|
| `Arch-Linux-x86_64-cloudimg.qcow2` | Official Arch cloud image, checksum verified |
| `working.qcow2` | Provisioning overlay (base image stays pristine) |
| `baseline.qcow2` | Clean snapshot produced after provisioning |
| `baseline.qcow2.sha256` | Checksum of the clean snapshot |
| `runs/<name>.qcow2` | Disposable overlay backed by `baseline.qcow2` |
| `seed.iso` | cloud-init NoCloud seed |
| `id_ed25519` | Test-only SSH key (never reused elsewhere) |
| `serial.log` | Boot/serial console of the provisioning VM |
| `ota/` | Official Waydroid system/vendor zips + SHA-256 used to seed P0-8.2 offline |

The guest is reachable only through a QEMU user-mode NAT forwarded to
`127.0.0.1` (provisioning: `2222`, runs: `2223`). No bridged or host network is
exposed.

## What the guest contains

- Arch Linux, updated, with the stock Arch kernel.
- `waydroid` installed but **not initialized** (the clean baseline).
- The stock Arch kernel ships the Rust binder driver and the `binder`
  filesystem, not a `binder_linux` module. Waydroid mounts binderfs and
  allocates the device nodes itself; provisioning verifies `/proc/filesystems`
  contains `binder`. The manual probe created `binder`/`hwbinder`/`vndbinder`;
  Waydroid's own driver selection during P0-8.2 used the `anbox-*` names,
  which is equally valid (both are binderfs nodes).
- `weston` plus `/usr/local/bin/wayland-headless` for a headless Wayland
  session (`weston --backend=headless-backend.so`).
- `polkit` (with `pkttyagent`), `android-tools`, `git`, `python`,
  `squashfs-tools`, `lzip`, `xdg-utils`, `alacritty`, `dbus`, `curl`.
- User `tester` with a test-only SSH key and passwordless sudo.
- Test data in `/home/tester/test-data/`:
  - `invalid.apk` — a non-APK file for negative tests.
  - `F-Droid.apk` — official, freely redistributable APK fetched from
    `https://f-droid.org/F-Droid.apk` (best effort; re-download if absent).
- `/home/tester/PROVISIONED` marker written only after every provisioning step
  succeeded.

## Usage

```bash
scripts/test-vm/vm.sh provision    # download, cloud-init, boot, wait for SSH
scripts/test-vm/vm.sh ssh          # inspect the clean provisioning VM
scripts/test-vm/vm.sh stop         # graceful shutdown
scripts/test-vm/vm.sh snapshot     # commit working.qcow2 -> baseline.qcow2
scripts/test-vm/vm.sh run scenario # fresh disposable overlay from baseline
scripts/test-vm/vm.sh ssh-run scenario
scripts/test-vm/vm.sh stop-run scenario
scripts/test-vm/vm.sh status
```

Each P0-8.2 scenario must start from a fresh `run` overlay. When the scenario
is done, delete `runs/<name>.qcow2` (and its serial log) to discard every
change. The baseline is never written to.

## Security rules

- The VM is for tests only; do not copy host SSH keys, browser profiles, app
  data, or credentials into it.
- The test key is generated for this VM only. Delete `id_ed25519` together with
  the VM directory when P0-8 is finished.
- Sudo is passwordless inside the guest on purpose. The guest has no route to
  the host filesystem; QEMU user-mode networking only forwards SSH to
  `127.0.0.1`.
- The baseline is recreated when the provisioning recipe changes; never reuse a
  baseline whose provenance is unknown.

- [x] `bash -n scripts/test-vm/vm.sh` passes.

baseline itself must stay untouched.
